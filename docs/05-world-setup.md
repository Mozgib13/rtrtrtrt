# 05. Настройка мира после сборки: объекты, navmesh, производительность

Голая земля готова — вы в TB/World Editor'е расставляете контент.

## 5.1 Чем расставлять объекты

Два рабочих пути:

1. **Terrain Builder** (`Add Objects`) — объекты «впечены» в мир навсегда.
   Плюс: не грузит старт сервера ничем. Минус: всё ручное; для процедурных
   систем (лес вдоль дороги, дома кварталами) — неудобно.
2. **DayZ Editor** (входит в DayZ Tools) — удобная расстановка, скрипт-экспорт,
   затем импорт обратно в TB. Плюс: быстро; минус: если оставить объекты
   скриптом, они спавнятся на старте сервера — на больших городах это больно.
   Рекомендуемый пайплайн для города: Editor для массовой расстановки →
   экспорт в TB → rebake.

Где найти модели: `P:\DZ\` (например, `P:\DZ\structures_sakhal`, `...\structures\...`,
`P:\DZ\plants_sakhal` и т.д.). В TB: **Object Library** → поиск по имени
(например, `Land_House`, `Land_Barn`, `Land_Ind`, `Land_Village`, `Military`, `Wooden`).

## 5.2 Что обязательно сделать в городе

1. **Здания.** Кварталы уже намечены бетоном в маске — ориентируйтесь на них
   (полигоны `URBAN` в `tools/generate_terrain.py`). Плотность: как в Черноруси
   сельские зоны — 12–25 m между домами; в «центре» — сплошной ряд пятиэтажек/хрущёвок.
2. **Дороги объектами — НЕ ОБЯЗАТЕЛЬНЫ.** У нас дороги запечены в текстуру
   (так проще и легче для сервера). Если хотите объёмные обочины/светофоры/знаки —
   расставьте вручную точечно.
3. **Мосты — ОБЯЗАТЕЛЬНЫ как объекты.** Текстурные мосты в маске выглядят
   «нарисованными», рельеф под ними есть, а пролёта нет. Возьмите из `P:\DZ\`
   подходящий автомобильный пролёт (например, из наборов Sakhal/Livonia,
   ищите `Bridge`, `Land_Bridge`) и поставьте по нашим координатам мостов
   (`docs/09-coordinates.md`). ЖД-мост (z≈3860–3880) — отдельный объект.
4. **Столбы ЛЭП, вышки, заборы** — по вкусу (производительность!).
5. **Деревья/кусты** — лучше всего через TB Terrain Processor (шум → плотность),
   см. `tools/dayz_tools/terrain_processor` в любом гайде по TB: шейп "forest",
   плотность выше в таёжных пятнах маски.

## 5.3 Navmesh (зомби смогут ходить по городу)

Навмеш — это бинарная сетка достижимости для ИИ. Без него зомби либо не появятся,
либо будут стоять.

1. TB → **Tools → Navmesh** (или отдельная кнопка Navmesh в тулбаре TB,
   зависит от версии DayZ Tools).
2. Укажите параметры: tileWidth 50, cellSize 0.25/0.1/0.1, seedPosition {6144,0,6144}
   (уже прописаны в нашем `world\config.cpp`).
3. Старт генерации → получите `P:\Krasnoyarsk\navmesh\navmesh.nm`.
   (Время: от десятков минут до нескольких часов на 12×12 км.)
4. `P:\Krasnoyarsk\navmesh\` упакуйте в `Krasnoyarsk_navmesh.pbo` со `$PBOPREFIX$` = `Krasnoyarsk\navmesh`.

Если пока не генерация — впишите во `world\config.cpp` вместо navmeshName
ссылку на `\DZ\worlds\chernarusplus\navmesh\navmesh.nm` — сервер стартует,
зомби будут «плавать» логически, но игра не упадёт. Как только сгенерите свой —
вернёте ссылку.

## 5.4 Производительность 12×12 км

- В `world\config.cpp` уже стоят ванильные дефолты (`clutterGrid=1`,
  `clutterDist=125`, `minTreesInForestSquare=3`). Если FPS на слабых ПК проседает —
  уменьшите `clutterDist` до 85 и `fullDetailDist` до 12.
- Не ставьте тысяч деревьев объектами — используйте Terrain Processor (они
  рисуются как «растительность», а не объекты).
- Помните про сервер: каждый ОБЪЕКТ = сетевой репликатор. 50 000 деревьев-объектов =
  мёртвый сервер; 500 домов + растительность = нормально.

## 5.5 Подписи объектов (Names) — расстояния уже прописаны

В `world\config.cpp` заполнен класс `Names` (Центр, Советский, Емельяново,
Столбы, Промзона, остров). Если игра ругается на секцию — просто удалите класс
`Names { ... };` целиком: это косметика на карте.

Дальше: `docs/06-pbo-build.md`.
